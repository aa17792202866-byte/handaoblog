二、数据库操作准备

以下数据库示例使用 MySQL 和 PyMySQL，假设数据库 ceshi 已经存在。各题示例共用连接对象 con 和游标 cu。

写法作用
con.cursor()创建执行 SQL 的游标
cu.execute(sql)执行一条 SQL
cu.execute(sql, params)绑定参数后执行 SQL
cu.fetchone()获取一条查询结果；没有结果时返回 None
cu.fetchall()获取所有剩余查询结果
autocommit=True自动提交每条语句的修改

默认游标的单条查询结果通常是元组，例如 (800.00,) 的结构。金额使用 DECIMAL 时，Python 中实际得到的值通常是 Decimal 对象。

参数化 SQL： SQL 中用 %s 表示数据占位符，实际值通过第二个参数传入。不要给占位符额外加引号，也不要使用字符串拼接把用户输入塞进 SQL。

总容量为 3 × 3 = 9，能够容纳 8 人；本题最终人数一定是 3、3、2 的某种排列。

3. 方法二：打乱后均匀分组

本题中，8 // 3 = 2，8 % 3 = 2：每个办公室先分 2 人，再随机选 2 个办公室各多分 1 人。

4. 易错点

  • 原判断 len(a) < office_num * 3 漏掉了“人数恰好等于容量”的情况。允许分配的条件应为 <=，或用 > 判断容量不足。

  • 提前创建所有办公室，人数少时也能显示空办公室，避免编号缺失后按 dict1[j + 1] 访问出错。

  • random.shuffle() 原地修改列表，返回 None，不能写成 teachers = random.shuffle(teachers)。

  • random.sample() 是不重复抽样，适合选出需要多分 1 人的办公室。

  • 切片 teachers[start:start + count] 包含左端，不包含右端。

  • 方法二还保证人数尽量均匀；对于其他人数，方法一只保证不超容量。

七、列表题 2：不使用内置排序完成升序排列

1. 题目

将下列列表从小到大排序，不能使用 sorted() 或 list.sort()：

2. 原作业思路

原代码通过双重循环比较交换完成排序。它不是标准的“相邻元素比较”冒泡排序，比较范围也有重复。

3. 更便于理解的冒泡排序

预期结果：

循环含义： 每轮比较相邻元素，把较大的值向右移动。一轮结束后，未排序部分的最大值到达右端；右端已排好的部分不再参与下一轮比较。如果整轮没有交换，说明列表已排好序。

  • n - 1 - i：逐轮缩小比较范围，也保证 j + 1 不越界。

  • a, b = b, a：交换两个值，无需手动创建临时变量。

  • 冒泡排序最坏时间复杂度为 O(n²)；以上提前退出版本在输入已升序时为 O(n)，额外空间为 O(1)。

八、列表题 3：字符串中的第二大数字

1. 题意理解

按原作业思路，“数字”指字符串中的单个数字字符，“第二大”指去重后的第二大值，并非提取完整的多位整数。

例如 adv123512 中，不同数字为 1、2、3、5，第二大数字为 3；999 只有一种数字，返回 -1。

2. 参考代码

3. 解题步骤

  1. 遍历字符串，只保留 0～9。

  2. 使用 int() 将字符转成整数。

  3. 使用集合去重。

  4. 判断不同数字是否至少有 2 个。

  5. 降序排序后，取下标为 1 的元素。

4. 为什么调整 isdigit()

原代码使用 ch.isdigit() 筛选字符。对于常见的 0～9 没问题，但某些字符（例如 ²）也会使 isdigit() 返回 True，却不能直接用 int() 转换。这里明确只处理普通数字字符，避免这种情况。

九、原文件运行状态与复习要点

原文件中大多数解题代码被 # 注释，部分代码位于三引号字符串中，因此不会作为 Python 语句执行。目前会执行的主要内容是：连接数据库、创建 user_mail 表、手动排序并打印结果。如果数据库连接失败，后面的排序也不会运行。

复习时重点检查：

  • 能否正确区分 INSERT、UPDATE、SELECT、DELETE？

  • SQL 占位符中的值是否通过参数传入？

  • 字段类型和名称是否符合含义，例如金额、成绩、总分？

  • 循环是否包含正确的起止范围，是否一定能够结束？

  • 容量刚好足够、没有数据、只有一种数字时能否正确处理？
