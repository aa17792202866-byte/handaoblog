Git 如何查看 SSH 连接的远程仓库、账号和密钥

“Git 的 SSH 远程连接是什么”可能指几个不同的问题：代码从哪个仓库拉取、推送到哪里、实际连接哪台主机、使用哪个平台账号，以及最终通过哪把密钥完成认证。这几项需要分别查看。

本文以 Windows PowerShell 和 GitHub 为例。除特别说明外，Git 命令在需要检查的本地仓库目录中执行；示例中的 example-owner、demo-repo、example-user 和 github-work 都是演示值，需要按自己的配置替换。

先用这几条命令定位问题

想查看什么 命令 是否连接网络
当前仓库的远程地址 git remote -v 否
origin 的推送地址 git remote get-url --push --all origin 否
GitHub 识别到哪个账号 ssh -T git@github.com 是
SSH 实际采用的主机与候选密钥配置 ssh -G git@github.com 否
SSH 尝试了哪些密钥 ssh -vT git@github.com 是
当前仓库能否读取远程引用 git ls-remote origin 是

如果远程地址使用 SSH 别名，例如 github-work，后面的 SSH 命令也要使用这个别名，才能检查相同的配置。

各部分的含义是：

  • origin：本地给这个远程仓库起的名字，可以有其他名字，也可以同时配置多个远程仓库。
  • (fetch)：获取远程内容时使用的地址。
  • (push)：向远程推送时使用的地址。
  • github.com：SSH 连接目标，可以是真实主机名，也可以是 SSH 配置中的别名。
  • example-owner/demo-repo.git：仓库所属用户或组织，以及仓库名。
  • git@：GitHub 的 SSH 连接用户；平台通过密钥识别具体账号。

这里的 example-owner 是仓库所有者，不一定是本次认证所使用的账号。例如，自己的账号可能拥有某个组织仓库的访问权限。

如果地址是 https://github.com/...，这个远程地址采用 HTTPS。直接运行 ssh -T 测试成功，也不能证明该 HTTPS 地址正在使用 SSH。

重点看：

  • hostname、port：配置中的目标主机与端口。
  • user：SSH 用户。
  • identityfile：配置的候选身份文件，可能不止一项。

ssh -G 显示的是配置，不是一次成功连接的记录。 它不会完成网络连接，也不能单凭某个 identityfile 就认定该密钥最终认证成功。参数说明见 OpenSSH：ssh 和 ssh_config。

确认 Git 自己有没有覆盖 SSH 设置

直接在终端运行 ssh，不一定与 Git 启动的 SSH 命令完全相同。Git 可能设置了专用命令、密钥路径，或使用了另一套 SSH 程序。

它们决定提交记录中的作者信息，不决定 SSH 使用哪个 GitHub 账号登录。排查账号时，应分别检查：

  1. git remote -v：目标仓库地址。
  2. ssh -T：服务端识别到的认证身份。
  3. ssh -vT：实际认证过程和密钥选择。
  4. git config user.name、git config user.email：提交署名。
