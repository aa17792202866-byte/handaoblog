WordPress数据库表结构与常用查询笔记

这篇笔记根据一份实际的 wordpress_db.sql 导出文件，整理 WordPress 各张数据表的作用、关键字段、关联关系和常用查询。分析针对导出时的快照，不代表网站之后的实时状态。

一、SQL 文件里保存了什么

这份文件由 Navicat 导出，包含 MySQL 建表语句和数据插入语句，共有 12 张 WordPress 标准表，没有额外的插件专用表。

数据库保存文章、评论、账号、权限、网站设置等信息，但不包含 WordPress 程序、主题和插件的代码，也不包含上传图片的原始文件。

完整恢复网站通常还需要：

  • WordPress 网站文件，尤其是 wp-content 下的主题、插件和上传目录。
  • 正确配置的 wp-config.php，包括数据库连接信息和表前缀。
  • 与网站匹配的 Web 服务和 PHP 运行环境。

下文统一使用备份中的 wp_ 前缀。其他网站可能使用不同前缀，执行查询前应确认实际表名。

二、12 张表的作用总览

表名 主要用途 本次备份记录数
wp_users 用户账号和密码哈希 1
wp_usermeta 用户角色、权限和个人设置 19
wp_posts 文章、页面、导航、样式和修订记录 7
wp_postmeta 内容的附加属性 3
wp_comments 评论正文及评论者信息 1
wp_commentmeta 评论附加属性 0
wp_terms 分类、标签等词条的名称 2
wp_term_taxonomy 词条所属的分类体系 2
wp_term_relationships 内容与分类词条的关联 2
wp_termmeta 分类词条的附加属性 0
wp_options 全站设置、缓存和定时任务 158
wp_links 旧版友情链接和书签 0

空表不等于网站异常。例如没有评论扩展信息时，wp_commentmeta 可以为空。

三、用户账号与权限

1. wp_users：用户基本信息

这张表回答“用户是谁、用什么账号登录”。

字段 含义
ID 用户唯一编号
user_login 登录用户名
user_pass 密码哈希，不是明文密码
user_nicename 作者链接等位置使用的用户别名
user_email 用户邮箱，可用于通知和密码找回
user_url 用户个人网站
user_registered 注册时间
user_activation_key 密码重置等流程使用的临时验证信息
user_status 历史兼容字段，不应理解为管理员权限或通用启停开关
display_name 页面上显示的作者名称

本次备份只有一位用户，用户 ID 为 1。文章不记录该用户的邮箱、密码哈希等私人信息。

管理员权限不直接存放在 wp_users，而是保存在 wp_usermeta。

2. wp_usermeta：用户权限和个人偏好

它采用“属性名称 + 属性值”的方式，为用户补充信息。

字段 含义
umeta_id 属性记录编号
user_id 所属用户，对应 wp_users.ID
meta_key 属性名称
meta_value 属性内容

本次备份中有 19 条用户属性，主要包括：

meta_key 作用
nickname 昵称
first_name、last_name 姓名
description 用户个人简介
admin_color 后台配色
rich_editing、syntax_highlighting 编辑器偏好
show_admin_bar_front 前台是否显示工具栏
locale 用户语言偏好
wp_capabilities 用户角色和权限，本次用户具有管理员角色
wp_user_level 兼容旧版的用户等级
session_tokens 登录会话的校验信息、有效期及相关登录信息
wp_persisted_preferences 编辑器布局等个人设置

wp_capabilities 中的 wp_ 与表前缀有关，其他前缀的网站可能使用不同的键名。

session_tokens 不应作为普通配置公开分享。它不是用户明文密码，也不能用来反推出密码。

四、文章、页面与内容属性

3. wp_posts：不只是文章

WordPress 将多种内容放在同一张表，通过 post_type 区分。

本次备份的 7 条记录为：

ID 标题 post_type 状态或用途
1 世界，您好！ post 已发布的默认文章
3 隐私政策 page 草稿页面
5 导航栏 wp_navigation 区块导航内容
7 Custom Styles wp_global_styles 全站样式设置
9 导航栏 revision ID 5 的修订版本
10 导航栏 revision ID 5 的另一个修订版本
13 自动草稿 post 编辑器自动生成的草稿

因此，7 条记录不等于发布了 7 篇文章。本次只有 1 篇已发布文章。

主要字段：

字段 含义
ID 内容编号
post_author 作者编号，对应 wp_users.ID
post_title 标题
post_content 正文，可包含 HTML、区块标记或配置内容
post_excerpt 摘要
post_status 状态，如 publish、draft、auto-draft、trash
post_type 内容类型，如 post、page、attachment、revision
post_name URL 使用的内容别名
post_parent 上级内容编号，例如修订版本所属的原内容
post_date、post_date_gmt 发布时间及对应 GMT 时间
post_modified、post_modified_gmt 修改时间及对应 GMT 时间
comment_status 是否允许评论
ping_status 是否允许 pingback、trackback 等相关交互
post_password 内容访问密码，与后台用户密码不是一回事
guid 内容的持久标识，不应作为普通网址随意批量替换
menu_order 排序值，页面等内容可能使用
post_mime_type 附件的 MIME 类型
comment_count 评论计数

附件一般以 attachment 类型保存记录，图片文件本身通常位于 wp-content/uploads。本次备份没有附件记录。

4. wp_postmeta：内容的附加信息

正文和标题在 wp_posts，附加设置在 wp_postmeta。

字段 含义
meta_id 属性记录编号
post_id 所属内容编号，对应 wp_posts.ID
meta_key 属性名称
meta_value 属性内容

这张表可保存特色图片编号、页面模板、自定义字段、附件文件位置以及插件配置等。

本次实际只有 3 条：

  • 隐私政策页面的 _wp_page_template = default，表示使用默认模板。
  • 两条 _edit_lock，记录文章或页面的编辑锁信息，帮助减少多人同时编辑冲突。

_edit_lock 是编辑协作信息，不是文件系统权限或数据库锁。

五、评论与评论属性

5. wp_comments：评论正文与审核状态

字段 含义
comment_ID 评论编号
comment_post_ID 评论所属内容，对应 wp_posts.ID
comment_author 评论者名称
comment_author_email 评论者邮箱
comment_author_url 评论者网址
comment_author_IP 评论者 IP
comment_content 评论正文
comment_approved 审核状态，如已批准、待审核、垃圾评论
comment_parent 被回复的评论编号，0 通常表示顶层评论
user_id 已登录评论者的用户编号，匿名评论通常为 0
comment_type 评论类型
comment_date、comment_date_gmt 评论时间及对应 GMT 时间
comment_agent 评论时记录的客户端信息

本次只有安装 WordPress 时生成的默认欢迎评论，关联文章 ID 1。

6. wp_commentmeta：评论的扩展信息

通过 comment_id 关联 wp_comments.comment_ID，使用 meta_key、meta_value 保存附加属性，例如反垃圾插件的检测结果。

本次为空，不影响已有评论的正文和审核状态。

六、分类、标签与内容之间的关系

分类相关内容主要分散在 3 张表：名称、分类体系、关联关系。另有一张属性表补充词条信息。

7. wp_terms：词条名称

字段 含义
term_id 词条编号
name 显示名称
slug URL 或内部识别使用的别名
term_group 词条分组，普通使用中较少关注

本次包含 未分类 和 twentytwentyfive 两个词条。

仅看这张表，无法判断一个词条是文章分类、标签还是主题标记，需要结合 wp_term_taxonomy。

8. wp_term_taxonomy：词条所属类型

字段 含义
term_taxonomy_id 词条与分类体系组合的编号
term_id 对应 wp_terms.term_id
taxonomy 分类体系，如 category、post_tag、wp_theme
description 描述
parent 层级分类的父词条 ID
count 关联对象计数，由 WordPress 按对应分类体系维护

本次实际对应关系：

词条 taxonomy 含义
未分类 category 文章分类
twentytwentyfive wp_theme 主题标记，不是普通文章分类

9. wp_term_relationships：内容属于哪个分类

字段 含义
object_id 对象编号，本次数据中对应 wp_posts.ID
term_taxonomy_id 对应 wp_term_taxonomy.term_taxonomy_id
term_order 关联顺序

本次有两条关系：

注意，term_relationships 连接的是 term_taxonomy_id，不能直接把它当成 term_id 使用；即使本次数据里部分编号恰好相同，两者含义也不同。

这种结构支持一篇文章拥有多个分类和标签，也支持一个分类包含多篇文章。

10. wp_termmeta：词条附加属性

通过 term_id 关联 wp_terms.term_id，用 meta_key、meta_value 保存分类图片、自定义颜色或插件增加的词条信息等。

本次没有记录。

十、实际维护时容易混淆的地方

  • WordPress 后台账号在 wp_users，与 SSH 用户和 MySQL 用户是不同的账号体系。
  • 数据库中有密码哈希，不意味着能读取原密码；密码重置应优先通过后台或官方恢复流程。
  • 用户角色在 wp_usermeta，角色所包含的权限定义通常在 wp_options。
  • 内容总行数包含页面、修订和样式等，不能直接作为文章数量。
  • 数据库备份不等于完整网站备份，媒体文件和主题代码需要另外保存。
  • 数据库导出文件可能包含账号资料、登录会话和恢复信息，不应随博客文章公开上传原始 SQL。
  • 修改、删除数据前应备份，并确认操作的是正确网站的数据库，尤其是存在多个 WordPress 数据库时。
