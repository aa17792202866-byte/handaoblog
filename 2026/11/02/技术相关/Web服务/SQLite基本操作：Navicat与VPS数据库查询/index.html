SQLite基本操作：Navicat与VPS数据库查询

记录 SQLite 的基本操作，包括在 Navicat 查看数据库、在 Ubuntu VPS 上查找和查询 .db 文件，以及导出、备份和常见错误排查。使用 3x-ui 常见的 /etc/x-ui/x-ui.db 作为查询示例；不同软件和版本的路径、表名、字段可能不同，应先查看实际结构。

一、SQLite 和 MySQL 有什么区别

SQLite 是嵌入式数据库，常见形式是一个数据库文件，由程序直接读取。MySQL 通常由数据库服务进程接收客户端连接，使用单独的数据库账号进行认证。

对比项 SQLite MySQL
常见访问方式 打开数据库文件 连接数据库服务
查询工具 sqlite3、Navicat 的 SQLite 连接等 MySQL 客户端、Navicat 的 MySQL 连接等
是否有数据库服务端口 通常没有 常见为 3306，具体以配置为准
查看表 查询系统结构表，或在 CLI 中使用 .tables SHOW TABLES;
查看数据库 PRAGMA database_list; 查看当前连接的数据库 SHOW DATABASES;

即使改对拼写，也不能把 MySQL 的语法直接搬到 SQLite。.db 只是扩展名，不能仅凭后缀确定文件一定是 SQLite。

十、常见报错和排查方向

现象 常见原因 检查方向
near "SHOW": syntax error 使用了 MySQL 语法 改用 PRAGMA、系统结构表查询
near ".": syntax error 在 SQL 窗口执行点号命令 Navicat 使用 SQL，点号命令放在原生 sqlite3 CLI 中
unable to open database file 路径错误、文件或目录权限不足 检查文件是否存在、父目录是否可访问
no such table 打开错库、表名不同，或误创建空库 使用 PRAGMA database_list; 和表清单核对
no such column 字段名或软件版本不同 先执行 PRAGMA table_info(...)
attempt to write a readonly database 只读连接执行了写操作 区分查看数据与修改数据库；不要直接放宽在线库权限
database is locked 其他连接正在写入或持有事务 缩短事务、适当等待，不删除 WAL/SHM 文件
file is not a database 文件不是 SQLite、是文本 SQL、已加密或损坏等 先确认文件类型和来源
下载后数据比面板旧 下载了旧副本，或复制主文件时遗漏 WAL 内容 重新使用 .backup 制作一致快照

十一、常用命令速查

目标 Navicat 或 sqlite3 中的 SQL 原生 sqlite3 点号命令
查看当前数据库文件 PRAGMA database_list; .databases
查看表 查询 sqlite_master .tables
查看字段 PRAGMA table_info(client_traffics); .schema client_traffics 查看完整结构
查看前 20 条数据 SELECT * FROM client_traffics LIMIT 20; 直接执行左侧 SQL
查看记录数 SELECT COUNT(*) FROM client_traffics; 直接执行左侧 SQL
查看值的实际类型 SELECT typeof(up) FROM client_traffics LIMIT 1; 直接执行左侧 SQL
退出命令行 不适用 .quit
