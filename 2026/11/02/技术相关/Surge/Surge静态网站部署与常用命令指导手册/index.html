Surge 静态网站部署指导手册：Windows 操作、自定义域名与常用命令

本文记录如何在 Windows 上使用 Surge.sh 发布静态网站，并整理更新、域名绑定、预览、回滚和故障排查的常用命令。

以下操作以已经部署的“韩导的小工具”为例。文中的本机目录与域名是本次项目的实际值，部署其他项目时需要换成自己的值；账号密码通过 CLI 提示输入，不写进文章或脚本。

一、先理解 Surge 发布的是什么

Surge.sh 是静态网站托管平台，用来发布 HTML、CSS、JavaScript、图片等文件。它与手机、Mac 上的 Surge 网络代理软件不是同一款产品。官方 CLI 介绍

这次的网站没有应用后端：Markdown、Word 和 PDF 的转换由访问者的浏览器完成。因此，可以直接发布完整网页目录。

六、绑定自己的子域名

本次使用 tools.hanruixuan.com，保留原来的主站解析，只给 tools 新增一条记录。

在当前 DNS 服务商的管理页面填写：

配置项 值
记录类型 CNAME
主机记录 / 名称 tools
目标 / 记录值 geo.surge.world
TTL 自动

当前官方推荐的 CNAME 目标是 geo.surge.world；旧的 geo.surge.sh 也仍受支持。以发布时提示和 自定义域名文档 为准。

如果这个子域名已有其他 A、AAAA 或 CNAME 记录，先确认它们的用途，再调整成指向 Surge 的记录；不要让同一个主机名同时指向不同托管平台。

如果使用 Cloudflare，可以先用“仅 DNS”模式完成验证，减少代理带来的排查变量。已有主站使用的端口重写规则应只匹配原主站，不要让新子域名也被改写到 VPS 的 8443。

十二、常见问题排查

1. 只显示命令列表，没有上线网址

检查是否只输入了一个目录。补上 publish，或者在目录后明确指定域名。看到帮助列表不代表发布成功。

2. 发布成功，但自定义域名打不开

先执行 status。检查子域名的 DNS 记录、证书状态和账号验证提示，不要立即重复上传文件。Windows 也可以查询解析：

如果启用了 DNS 代理或域名级端口重写，还应检查相应规则是否误匹配了 tools。

3. 上线后样式、脚本或图片丢失

确认发布的是完整目录，而不是单个 index.html。检查路径大小写、相对路径，以及 vendor 是否随包上传。可使用 debug files 对照线上文件列表。

4. PDF 转 Markdown 失败

本项目依赖 PDF.js 模块和 Worker。可以先检查两个请求：

确认不是 404，并检查浏览器开发者工具的 Console、Network。JavaScript 模块必须返回浏览器支持的 JavaScript 内容类型；不能只凭网页首页正常就判断 PDF 功能已通过验证。MDN：JavaScript 模块排查

本文不把这项要求等同于 Surge 已对当前项目验证通过，发布后仍要实际导入一个文字型 PDF 测试。

5. 更新后仍看到旧页面

先确认改的是本地发布目录，再检查 CNAME 和发布目标。然后强制刷新浏览器，必要时使用 debug bust。回滚过的项目还应检查当前正式版本是否符合预期。
