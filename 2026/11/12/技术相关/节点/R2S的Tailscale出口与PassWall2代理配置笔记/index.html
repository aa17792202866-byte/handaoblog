R2S OpenWrt：Tailscale 出口、远程管理与 PassWall2 HTTP 代理

记录 R2S 使用 OpenWrt 时，如何提供 Tailscale 出口节点、通过虚拟 IP 管理路由器，以及在 WAN 口连接主路由的情况下提供 PassWall2 HTTP 代理。

一、当前网络与已知结果

项目 当前信息
设备 R2S，运行 OpenWrt，使用 PassWall2
网线连接 R2S WAN 口连接主路由 LAN 口
主路由地址 192.168.31.1
R2S 局域网可达地址 192.168.31.112，本文按它属于 WAN 接口说明，实际以接口页面为准
R2S Tailscale IPv4 100.86.215.11
已确认结果 手机将 Tailscale 出口节点选择为 R2S 后，可以访问需要代理的网站
尚待验证 手机直接修改网关后的效果，以及新建 HTTP 代理端口后的连通性

两个 IP 的用途不同：192.168.31.112 用于家庭局域网访问，100.86.215.11 用于 Tailscale 网络访问。Tailscale 的 100.x 地址不是公网 IP。

前提：R2S 本身可以上网，已经安装、启动并登录 Tailscale。以下命令在 R2S 的 SSH 终端中用 root 执行。

若提示没有登录，先执行 tailscale up，按输出链接完成登录，再发布出口。若老版本不支持 tailscale set，应按版本支持情况处理；不要为了消除 tailscale up 的参数提示而随意重置已有配置。

3. 后台批准

打开 Tailscale 设备管理后台：

  1. 找到 R2S。
  2. 点击右侧菜单，选择 Edit route settings。
  3. 勾选 Use as exit node。
  4. 保存。

如果已有自动批准策略，可能不需要手动批准。自定义过访问控制策略的网络，还应确认使用者具有访问互联网出口的权限。

4. 客户端选择出口

手机或电脑连接同一 Tailscale 网络，在客户端的 Exit Node／出口节点 中选择 R2S。每台客户端单独选择。

“允许访问本地局域网／Allow LAN access”控制的是客户端当前位置的局域网访问，不等于自动发布 R2S 家里的整个网段。

5. 确认实际出口

连接后查询公网 IP：

  • 流量由 R2S 经家庭宽带直连出去，通常显示家庭宽带公网 IP。
  • 流量被 R2S 或上游设备的代理接管，可能显示代理节点 IP。

因此，选中家里的 R2S 作为出口，并不保证所有网站都看到家庭宽带 IP。还取决于 PassWall2 分流和上游网络配置。

如果选择出口后无法上网，需检查 IP 转发、Tailscale 访问控制，以及 tailscale0 到实际上网接口的防火墙转发与 NAT。不能只凭“后台显示出口节点”判断整个链路正常。

OpenWrt 上还应在重启后确认出口设置是否保留；某些插件会在启动时根据自身配置重新设置 Tailscale。

四、WAN 接主路由 LAN，能否将 R2S 当作网关

可以配置实现，但不能保证只修改手机网关就能使用。

手机连接主路由 Wi-Fi，并将 IPv4 网关设为 192.168.31.112 后，发往外网的 IPv4 流量会先交给 R2S 的 WAN 接口，再由 R2S 处理并通过同一个接口交给主路由。

需要满足：

  1. R2S 允许从 WAN 进入的相关流量继续转发出去；OpenWrt 默认 WAN 区域通常限制转发。
  2. PassWall2 透明代理规则能够接管这一入口的流量。
  3. DNS、返回路径和必要的 NAT 配置正确。
  4. .112 地址固定且没有冲突，避免 DHCP 租约变化后网关失效。

仅开启路由器本机代理，不能证明它能够代理其他设备。手机只修改 IPv4 网关，也不代表 IPv6 流量会经过 R2S。

测试时先关闭手机 Tailscale 和其他代理，保留手机原来的 IP、子网前缀等信息，只调整需要测试的网关和 DNS；测试结束可恢复 DHCP 自动获取。以浏览器访问和实际出口 IP 为准。

LAN 口接主路由 LAN 是另一种常见旁路由方案，但当前 WAN 接法并非必须换线才能使用。如果切换接法，应先配置 R2S LAN 地址和 DHCP，不能假定原来的 WAN 地址会自动迁移到 LAN。

五、为什么 Tailscale 出口已经可以代理

两种方式在 R2S 上的流量入口不同：

方式 流量入口 需要检查的规则
手机 Tailscale 出口选择 R2S 隧道流量解密后通常由 tailscale0 进入 Tailscale 转发及相应代理规则
手机网关设置为 .112 R2S WAN 接口 WAN 转发及相应透明代理规则
手机配置 .112:HTTP端口 R2S 上运行的代理服务 WAN 入站端口、监听地址和代理节点

手机通过 Tailscale 出口已经能够访问需要代理的网站，说明这条实际路径能完成相应处理；但没有查看配置前，不能断言一定是 R2S 上的哪条规则或哪个代理接管了流量，也不能据此认定普通 WAN 网关转发同样可用。

六、用 PassWall2 提供 HTTP 代理

对于支持 HTTP 代理的浏览器和应用，可以让它们直接连接 R2S 的 HTTP 代理端口。即使 R2S 使用 WAN 口接主路由 LAN，这种方式也可以实现。

1. 开启代理监听

进入 服务 → PassWall2 → Socks 配置，添加或编辑一条服务。不同版本的入口和翻译可能略有区别。

配置项 示例设置
启用 勾选
节点 选择已经可用的代理节点；需要分流时选相应分流配置
绑定本机／Bind Local 取消勾选，以允许其他设备连接
Socks 监听端口 1081
HTTP 监听端口 1082

1081 和 1082 是本文示例，需要确认没有端口冲突。PassWall2 官方实现中 HTTP 端口设为 0 表示不启用；具备相应核心时才显示该选项。

“绑定本机”意味着只允许本机访问。供局域网使用时，应确认实际监听地址为 0.0.0.0、192.168.31.112 或其他能够接收该地址连接的监听方式，而不是仅监听 127.0.0.1。

保存并应用。必要时在 R2S SSH 终端检查：

没有输出时，先检查 HTTP 端口是否启用、相关核心是否运行，以及 PassWall2 日志。

2. 放行 WAN 入站的 HTTP 代理端口

因为 .112 属于 WAN 接口，手机访问这个服务会经过 WAN 入站规则。在 网络 → 防火墙 → 通信规则 中增加一条规则：

配置项 示例设置
名称 Allow-HTTP-Proxy
协议 TCP
源区域 wan，以实际接口所属区域为准
源地址 192.168.31.0/24，也可以缩小到指定设备 IP
目标区域 此设备／设备（输入）
目标端口 1082
动作 接受

这是连接 R2S 本机服务的规则，不需要为这个用途开放 WAN → WAN 转发，也不需要在主路由做端口转发。只开放需要的端口和来源即可，不要为此放开整个 WAN 区域。

3. 手机填写 HTTP 代理

手机连接主路由 Wi-Fi，在该 Wi-Fi 的代理设置中选择“手动”：

配置项 填写内容
代理主机名 192.168.31.112
代理端口 1082
手机网关 保持主路由 192.168.31.1 或原来的自动配置

手机通过 HTTP 代理服务发起请求，R2S 再按该服务所选择的节点或分流配置访问目标。该 SOCKS/HTTP 服务的节点选择需要单独确认，不能默认与透明代理完全相同。

HTTP 代理不能填写 SOCKS5 端口。 本文示例中，手机 Wi-Fi 手动代理填写 1082，不是 1081，也不是透明代理内部使用的端口。

4. 电脑测试 HTTP 代理

Windows PowerShell 中使用 curl.exe，避免某些版本中 curl 别名行为不同：

先关闭其他代理或 Tailscale 出口，便于隔离测试。如果端口不通，检查服务监听和防火墙；端口通但访问失败，再检查协议、节点和服务日志。仅看到 200 Connection established 不足以判断目标请求成功，还需观察后续 HTTPS 响应或报错。

5. HTTP 代理的范围

手机 Wi-Fi 手动代理通常只对遵循系统 HTTP 代理设置的应用生效。部分 App 不使用它，普通 UDP 流量也不会因此全部经过 HTTP 代理。

如需手机整体通过 R2S 上网，当前已经成功的 Tailscale 出口方案更符合这个需求；如需局域网设备透明代理，则继续配置旁路由网关方案。

七、三种方式如何选择

方式 客户端怎么设置 适合场景
Tailscale 出口 安装并连接 Tailscale，出口选择 R2S 异地通过家中 R2S 上网，当前已成功
旁路由网关 网关指向 R2S，配好转发、透明代理和 DNS 家中设备不安装客户端，按网关转发
HTTP 代理 应用或 Wi-Fi 填写 .112:1082 在家庭局域网中给支持代理的应用使用

需要远程管理 R2S，使用 Tailscale IP；需要在家庭局域网连接它的 HTTP 代理，使用局域网地址和 HTTP 端口。两者不要混淆。
