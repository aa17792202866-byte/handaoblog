八、常见问题

1. 提示 permission denied

如果错误指向 Docker socket，先用 sudo docker ps 检查。如果加上 sudo 能正常执行，通常应检查当前账号是否已加入 docker 组，以及是否完成重新登录。

不要通过把 Docker socket 改成所有人可写来解决权限问题。

2. 无法连接 Docker daemon

查看服务和近期日志：

服务未启动时可尝试：

如果启动失败，按日志排查。若提示系统未使用 systemd，当前环境超出了本文的服务管理前提，需要按该环境配置启动方式。

3. 安装软件包成功，但拉取镜像失败

APT 软件源和容器镜像仓库是不同的网络访问环节。先保留完整报错，区分连接超时、DNS、证书、身份认证或仓库限流，再处理对应问题；重新安装 Docker 通常不能解决镜像仓库访问故障。

4. 8080 端口被占用

查看监听情况：

也可以在启动示例时把宿主机端口换成 8081，保留容器端口 80，并同步修改测试地址。

5. 容器名称已存在

先查看 sudo docker ps -a。确认旧的 nginx-demo 是不再需要的测试容器后，再停止并删除它；也可以为新容器换一个名称。
